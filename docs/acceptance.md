# 真实账号验收

自动化测试模拟了 Telegram 与 Turnstile 返回值，不能替代真实平台的集成验收。部署前需要真实 Bot Token、管理员 ID、Cloudflare 账户；本文不假设已经完成云端验收。

## 部署

- [ ] 按[连接 GitHub 教程](deployment-manual.md)创建真正的 Fork，仓库显示 `forked from maodeyu180/TelegramDoor`。
- [ ] 先在同一 Cloudflare 账户创建专用 D1，默认名称为 `telegramdoor`。
- [ ] 从 Workers & Pages → Create application → Import a repository 连接 GitHub，直接选择自己的 Fork 部署。
- [ ] 根目录 `/`、生产分支 `main`、构建命令 `npm run build`、部署命令 `npx wrangler deploy`；前端只构建一次。
- [ ] 部署按名称找到现有 D1，绑定为 `DB`；没有手填数据库 ID、预先创建空 Worker 或手工建表。
- [ ] 如果令牌缺少 D1 读取权限，按排错文档补足权限后，在同一 Git 构建流程中成功重试。
- [ ] 三个密钥保存到 Worker 运行时「变量和机密」，名称无多余空格，生产部署已生效。
- [ ] 首次访问 `/health` 返回 `ok: true`，数据库自动初始化。
- [ ] 后台能登录；刷新保持登录；退出后原 Cookie 无法访问 API。
- [ ] 再次部署后，已有设置、封禁、消息对应关系、DB 绑定和控制台变量/密钥仍保留。
- [ ] 已通过验证的访客，在同一 D1 重新部署后可继续留言，不被要求重新答题。
- [ ] 后台登录和刷新时，状态读取中或读取失败不显示为尚未连接；已配置后默认显示检查连接，重新配置入口在连接维护中。
- [ ] 检查连接可区分地址匹配、地址不一致、未配置以及本地记录缺失；检查本身不会修改 Telegram 接收地址。
- [ ] 所有管理页面和手机布局正常；HTTPS 静态资源与 API 不报 CSP 错误。
- [ ] 管理员向机器人 `/start` 后，在后台连接并检查 Webhook，URL 指向自己的域名。
- [ ] Sync fork 后触发最新提交的构建；使用其他 D1 名称的旧部署按[更新说明](updating.md#先确认数据库名称)保留原数据库，没有误切换。
- [ ] 从旧独立副本迁到 Fork 时复用原 Worker 和 D1，运行时密钥仍生效。

## 双向私信

- [ ] 用第二个账号发送未验证消息，管理员不收到，后台拦截记录出现。
- [ ] 完成验证，再发送普通文本、带格式文本、图片、视频、语音、文件、贴纸、相册。
- [ ] 确认相册当前逐条显示，其他类型符合 Bot API 支持情况。
- [ ] 管理员收到原生「转发自…」消息；两侧无额外身份、表情、封禁按钮，验证题按钮正常。
- [ ] 管理员引用回复，访客端保留引用目标，且不暴露管理员个人账号；访客再次引用回复可正常送达，原生转发不附带引用关系。
- [ ] 访客隐藏转发身份或转发别人的内容时，引用 `/who`、回复和封禁仍对应实际访客。
- [ ] 两个访客交替留言和回复，确保不串人。
- [ ] 管理员不引用直接发文本、图片、语音或转发其他消息，均静默丢弃；编辑这些消息也不触发投递。
- [ ] 管理员引用自己的回复、后台回复镜像或帮助消息，均静默丢弃；引用访客来信才发送，命令仍能独立执行。
- [ ] 修改管理员回复的文本、媒体说明和支持编辑的媒体，检查对方更新。
- [ ] 编辑访客原生转发消息；Telegram 不允许时只提示访客重新发送，后台记录失败，没有重复转发或成功日志。
- [ ] 编辑成被过滤的链接后，对方保持原消息，后台记录拦截。
- [ ] 使用后台回复，确认管理员镜像引用对应访客的最近留言，无身份菜单，访客消息及后续引用都正常。

## 回应

- [ ] 管理员引用留言发送 `/react 👍`，访客原消息显示机器人回应。
- [ ] 访客引用管理员回复发送 `/react ❤`，管理员原消息显示回应。
- [ ] `/react 🥰` 等原六种以外的受支持表情，以及 `/react clear` 正常。
- [ ] 不支持的表情或消息只向操作者提示失败，不通知对方、不显示成功。
- [ ] 访客 `/react` 不能绕过验证、封禁、暂停、限频或操作其他人的消息。
- [ ] 私聊长按原生点赞不会被当作可同步能力宣传。

## 防骚扰

- [ ] `/ban`、`/ban 1h 原因`、显式 ID 封禁、后台封禁均有效。
- [ ] 被封禁用户继续发消息与 `/start` 时，不通知管理员，也不向用户持续回执；后台仍有记录。
- [ ] 旧的表情和验证按钮不能绕过封禁。
- [ ] `/unban` 后要求重新验证；临时封禁到期后可重新验证。
- [ ] 白名单可以跳过验证/过滤，但不能绕过限频和暂停。
- [ ] 验证失败 3 次进入冷却，冷却结束可重试；5 分钟过期挑战不能使用。
- [ ] 答对后原题变成「✅ 验证通过」且移除答案按钮；答错、过期、第三次失败均显示对应结果和下一步。
- [ ] 原题无法修改时可收到单独结果消息；重复点击不重复放行，也不把通过状态改回过期。
- [ ] Turnstile 在 Telegram 内置浏览器和常用浏览器中均可完成；错误域名、重复提交不能放行。
- [ ] 关闭文本记录后，新日志不再包含正文；保留期清理不删除黑名单。

## 运行

- [ ] 检查 Workers 请求量、CPU、D1 行读写量，确认符合自己的免费额度。
- [ ] 检查 Telegram 429 行为、用户屏蔽机器人行为以及 Worker 重试。
- [ ] 修改 Bot Token 后重新连接，并重新保存 Turnstile Secret。
- [ ] 导出/备份 D1，验证项目升级中的迁移过程。
